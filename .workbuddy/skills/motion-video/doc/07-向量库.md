# 07 · 向量库（Qwen3-VL-Embedding-2B · 离线语义检索底座）

> embed-server（2048 维跨模态：文本/图像/视频/片段可互搜）。定位：**离线批量 + 语义检索底座**，不占实时/门禁链路（视频 embedding ~34s/条、单实例独占 GPU）。

## 服务管理

```bash
cd code/tools/embed-server
python manage.py start     # 后台启动（uvicorn 127.0.0.1:8765，懒加载 ~20-60s）
python manage.py status    # /health 探活 + nvidia-smi 显存（bf16 ~4GB）
python manage.py stop
```

- 接口：`POST /embed {texts}` / `/embed-image {image}` / `/embed-video {video,frame_sample_num=8}` / `/embed-segments {items[]}`（片段默认 frames=4）；L2 归一化 2048 维。
- **GPU 独占约束**：单实例独占 GPU（再起实例即 CUDA OOM，总 7.96 GiB）；与其它本机 CUDA 任务排程（云端生图/DeepSeek 写稿不占本地卡，CosyVoice/TTS 与之分时）。
- 视频读取后端本机不可用（decord/torchcodec 均坏），统一 ffmpeg 抽帧兜底（t_i=(i+0.5)*dur/n，scale 最长边 560，单进程多 -ss）——此路径易碎，改动需回归。
- 模型目录：`D:/motion/models/Qwen3-VL-Embedding-2B`（`EMBED_MODEL_DIR` 可覆盖）。

## 两个落点

### 落点 A · 选题去重（research 阶段，先做、便宜）
`news-archive` 命名空间文本/封面向量：历史选题/历史新闻语义去重（补 score-and-rank 的 bigram Jaccard 之不足，跨模态：标题 vs 标题、封面 vs 封面）。
```bash
node scripts/vector-ingest.ts --text "OpenAI 发布 GPT-6" --ref <id> --namespace news-archive   # 入库
node scripts/vector-search.ts --namespace news-archive --text "<候选标题>"                    # 查重
```

### 落点 B · 成片片段复用（剪辑/总结阶段，离线批量）
`video-segments` 命名空间：成片切段入库（`--segments N`，均匀切 + prev/next 时序邻接链），新片按语义查复用片段（命中 global_start_sec/end_sec 定位）。
```bash
node scripts/vector-ingest.ts --video out/vN.mp4 --ref vN --segments 4 --desc "..."   # 入库（约 34s/段）
node scripts/vector-search.ts --namespace video-segments --text "模型发布"            # 语义定位片段
```

## 审查辅助（谨慎，不替代关卡 2/3）

命中可疑片段时，用 `video_segments` 的 prev/next 链还原前后上下文再喂视觉模型做局部重审——向量只定位、不降级完整审查。
