# 04 · 文案人工审查（门）

> 文案 = 视频的地基。**文案未过人工审查，禁止进入初稿视频生成**。这一步把问题拦在最便宜的阶段。

## 什么时候触发

方向工作流产出文案（新闻口播稿 / 项目介绍文案 / 实操解说稿）后、配音/渲染前。

## 审什么（按方向）

### 通用
- **口播稿规则**：每句一个信息点，钩子在第一句（数字/冲突）；13 句 ≈ 95s（短视频）；数字一律汉字（"197747"无法与"十九万七千"读音对位）；英文品牌词直接写（中英混合对齐已验证）。
- **字幕无标点**：句读全去，长句停顿靠拆句；唯一例外数字/型号间半角点号。
- **画面文字 ≠ 字幕重复**：画面上的文字是关键词级，不整句照抄字幕。

### 每日新闻（方向 1）
- **事实红线清单**：列"不可说错的数字/未验证数据不引用"；每个关键数字/结论必须带来源（research/ 存档）。
- 数字口径核对：涨跌幅/倍率/百分比换算复核；模型版本号、发布时间、公司名逐字核对。
- 立场与口径：AI 新闻避免厂商通稿腔；国内新闻遵守平台规范；娱乐新闻不传播未证实八卦。
- 来源行：成片引用的关键事实给 micro 来源（研究/官网/存档截图），禁止只存链接不留证据。

### GitHub 热点 / 个人项目（方向 2）
- **产品语义核对（引用权威源，禁止凭记忆）**：项目定位/功能/架构/模型名单必须来自仓库最新 README/SKILL/spec，不编造版本号与型号（教训：eduevidence 曾把用户真实模型名单当编造删除，返工一整天）。
- 介绍对象表述准确：介绍的是 Skill/产品/仓库，用词一致（如"8 个角色是用法组合"不是"规定死了 8 个"）。
- 开源/许可/作者信息核对；star 数、发布时间等时效数据标注采集日期。

### 实操录屏（方向 3）
- 步骤顺序与真实操作一致；快捷键/命令逐字符核对（**复制粘贴自真实终端/文档，禁手打"神似"**）。
- 涉及第三方产品时确认当前版本界面（录屏与口播描述版本一致）。

## 审查产物

`runs/<date>/<project>/copy-review.md`：
```markdown
# 文案审查
- 日期 / 方向 / 状态：approved | needs-change
- 事实红线清单（核对通过项 + 依据来源）
- 需修改项（列出原文→建议）
- 用户确认意见（approved 时间戳）
```

## 通过后

文案锁定（sha256 快照存 run 目录），才进入：配音 → 字级时间戳 → 分镜 → 初稿渲染。
之后文案的任何改动必须回到本门重审一次（快照对比 + 变更说明）。
