# 10 · 迭代进化（autosearch 式自我进化）

> 参考 `0xmariowu/Autosearch`（"self-evolving, gets smarter every time"）+ clusterclaw autosearch 的 experiment loop。**目标：每次做片都让 skill 变聪明一点，新会话无记忆也能从文件继续。**

## 四条机制

### 1. Session 文件（append-only 记忆）
每次做完一个视频，往 `runs/<date>/<project>/session.jsonl` **追加**一行：
```json
{"ts":"2026-09-04T10:00","project":"eduevidence-v1h","metric":{"render_count":6,"rework_rounds":2,"p0_p1_defects":3},"action":"渲染前 grep 旧名单防返工","status":"win"}
```
- append-only，禁改写历史行；新会话读它知道"以前怎么做的、指标如何"。

### 2. Living Document
`motion-video/doc/LIVING.md`（skill 目录内）持续维护：
- **目标**（当前主线 + 计划/方案文件路径）
- **已尝试**（做法 → 结果 → 判定 win/discard）
- **死胡同**（明确失败的做法 + 为什么）
- **关键胜利**（值得固化的做法）

> 新会话开工第一步：读 LIVING.md + 最近 session.jsonl，接着上次的假设继续。

### 3. Reflection block（每轮做完必写）
每次视频/每个修复轮次结束，写三条（追加进 session.jsonl）：
- (a) 高分做法的 top3 模式
- (b) 零收益/返工的做法
- (c) 下一轮的一个假设（可验证）

### 4. Post-mortem → 回写 patterns
- 每部片收尾时做 post-mortem：把 **winning/losing patterns** 提炼成可执行条目，回写对应 doc（如新踩坑 → doc/00 红线 或 方向 doc 的"经验"节；沿用 eduevidence-video-loop 模式，附日期）。
- **指标改善才保留**：做法必须能证明（返工次数下降/缺陷数下降/审查轮数下降/渲染次数下降），否则标 `discard` 进死胡同，不写进正典。

## 节奏模板（每次做片）

```
开工：读 doc/LIVING.md + 最近 session → 确定本次要验证的假设
过程：每个返工轮次都按"改前抽帧→改后抽帧→成片抽帧"留证（doc/00 质量纪律）
收尾：session.jsonl 追加 3 行 reflection → post-mortem 提炼 patterns → 回写 doc/ → 更新 LIVING.md
```

## 量化口径（给"指标改善"的定义）

| 指标 | 口径 |
|---|---|
| 返工次数 | 用户肉眼抓到并打回的轮数 |
| 缺陷数 | 审查报告 P0+P1 累计 |
| 渲染次数 | 每部片全渲/段渲次数（越少越好）|
| 审查轮数 | 关卡 2/3 实际轮数（≤3 封顶内越收敛越好）|

## 触发复盘的时刻

- 视频发布后（正常流程）。
- 用户中途纠正方向（如"介绍对象错了""这是真实模型名单"）——必写死胡同，防复发。
- 机器闸放过但用户抓到的缺陷——必回写（说明闸的盲区）。
