# 05 · 审查 3 轮（机器闸 → 独立 subagent → agy/Gemini 终审）

> 借鉴 video-talkcraft 三重验收 + 项目自有 agy 视频理解链路。**3 轮封顶**；第 3 轮失败走人工兜底。

## 关卡 1 · 机器闸（5 命令全 PASS 才进关卡 2）

```bash
# 在目标 Remotion 工程目录下执行（本 skill scripts/ 已自带）
python3 scripts/motion_check.py out/vN.mp4               # 画面健康：静止段 + 并发光栅抖动双判定
python3 scripts/card_lint.py <工程src> <slug,...>        # 动效卡保真：每张卡真实存在且相似度 ≥0.55
python3 scripts/beat_lint.py beats.json audio/timestamps.json --shots shots.json
                                                         # 词落点 |Δ|≤0.1s + 镜尾保护带 ≥0.5s
python3 scripts/sfx_check.py out/sfx-solo.wav cues.json  # 音效在场（峰值 ≥−45dBFS）
python3 scripts/sfx_check.py --mix out/vN.mp4 audio/full.wav cues.json   # 音效可听（掩蔽分级）
# 渲染前静态预检（零成本）：空台/状态切换窗
python3 scripts/beat_gap_check.py beats.json shots.json
```

评审材料抽帧（给关卡 2 的 subagent）：每句 2 帧 + 动效锚点帧（burst 锚点抽连拍三帧对）+ `contact_sheet.py` 拼 3×4 网格。

## 关卡 2 · 独立 subagent 审片（P0/P1/P2）

- **必须独立 subagent，禁制作者自评**：全新上下文（禁 fork 制作对话当评审、禁对同一评审做 followup 复审——否则自证闭环）。
- 评审材料四件套：① SHOTBOOK + 评审拼图 + 原帧目录；② 原版卡对比帧（gallery/media/<slug>.mp4 抽 2 帧 vs 成片对应帧，逐 slug 判"是不是同一张卡"）；③ 词落点核对表；④ 音效可听度报告。
- 按 rubric（可读性/构图/信息传达/质感/事实一致 + 保真/词落点）出 [P0/P1/P2]：
  - P0 = 观众必然察觉且伤害理解（事实/文字/字形错、不可读、声画错位、元素相撞遮正文、标注指错目标）
  - P1 = 违反硬规则或明显走样（错峰残影、词落点偏 >0.3s、整镜音效缺席、与原版卡明显不符）
  - P2 = 质感瑕疵（记录不挡验收）
- 修完 P0+P1 才算过关；修完 1 轮即交付并问用户是否续审（每轮全新上下文，累计封顶 3 轮；3 轮后仍有未清 P0/P1 停手，把清单+修复记录+为何没修掉交给用户定夺）。

## 关卡 3 · agy/Gemini 整片终审（视频理解）

`review-video.ts`（code/producer/scripts/）用 agy（Antigravity CLI，Google Gemini 终端 Agent）原生多模态整片观看：
```bash
npm run review:video -- <视频> --kind render --effort high --config ... --timeline ...   # 成片质检
npm run review:video -- repost/inbox/<id>/<视频> --kind repost --effort low             # 搬运合规预审
```
- 调用：`agy --model gemini-3.8-* --print-timeout 600s --print "<prompt 含 @视频路径>"`（评审任务要求用户指定 **gemini 3.8**；当前代码为 `gemini-3.7-flash-high/medium/low`，执行阶段升级模型名并保留 3.7 回退链：3.8 不可用 → 3.7-flash-high 并告知）。
- 鉴权：Google OAuth 登录态（`~/.gemini/antigravity-cli/`），不是 API key。
- 输出报告 schema：`{status, verdict: pass|warning|fail|unknown, issues[]{timestamp_sec, severity: high|medium|low, location, description, suggestion}, summary, model, ...}`。

### ★ 失败兜底（agy 不可用 → 人工审查 → 再发布）

agy 登录失效（`You are not logged into Antigravity`）/模型不可用/重试 3 次仍败时，**不要 exit(1) 硬阻断**：

1. 把完整审查 prompt（含 `@视频绝对路径` + 数据快照 + 预期时间轴段落表 + 检查清单 + JSON 输出契约——由 `review-video.ts` 的 `prompt()` 生成）落盘导出到 `runs/<date>/<run>/review/manual-prompt.md`。
2. 告知用户："agy 审查不可用（原因 X），已导出审查提示词到 <路径>，请你按提示词人工审查该视频；确认后可发布"。
3. 用户人工审查通过（回写 verdict 到 review/ 报告）→ 才允许进入发布（doc/06）。

执行阶段改造：`review-video.ts` 的 `available()` 增加登录预检（agy 试跑 `--model` 探测），失败走"导出 prompt + 提示人工审查"分支；打包硬门（create-package.ts）从"必须有 completed 报告"放宽为"completed 报告 **或** 用户已确认的人工审查记录"。

## 质量纪律（关卡 2/3 通用）

- 返修三纪律：批注帧三段闭环；状态动画修完整区间并集；二次返工留"上次为何失效"。
- 返修复核给量测数字（首次可辨时刻/被吞时刻/占比像素）。
- 用户批注的修复必须覆盖完整受影响区间（起点/中点/终点 + 边界前后）。
