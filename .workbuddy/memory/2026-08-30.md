## eduevidence-bilibili 引擎 GPU 硬件编码支持（Remotion NVENC）

### 结论
- Remotion 4.0.518 内置 ffmpeg（`node_modules/@remotion/compositor-win32-x64-msvc/ffmpeg.exe`）**带 h264_nvenc/hevc_nvenc**，系统 ffmpeg 同样带（RTX 5060 / 8GB / 驱动 610.47）
- `renderMedia` 传 `hardwareAcceleration: "if-possible"` 即可走 NVENC：Windows + codec=h264 → 选 `h264_nvenc`
- **实测 30 帧 verbose 日志**：第一遍 prespawnFfmpeg `-c:v h264_nvenc`（GPU 生效）；第二遍 stitchFramesToVideo `-c:a copy -c:v copy`（流拷贝，无重编码）。日志里 "Encoder: libx264" 是 generateFfmpegArgs 的误导性 verbose 打印，实际命令是 copy
- **陷阱**：若显式传 crf/encodingMaxRate/encodingBufferSize 会**静默禁用硬件加速**回退 libx264（hasSpecifiedUnsupportedHardwareQualifySettings）
- **concurrency 提速实测**：Ryzen 5 5600(6C/12T)+16GB，concurrency 1→4，600 帧 1080p@60 从"超时中断(101帧)"→ **35s 完整跑通**(601帧)（含 bundle）。内存 15.9GB 足够 4 并发

### 改动
- `engine/render_all.mjs` 已有 `hardwareAcceleration: "if-possible"`（未传 crf，✅ 正常走 NVENC）；concurrency 1→4
- `engine/render_preview.mjs`、`engine/test_render.mjs` **缺失**该配置 → 补上 `hardwareAcceleration: "if-possible"`；preview concurrency 1→4
- 临时验证脚本 verify_nvenc.mjs 已删除（验证完成）

## embed-server GPU 视频嵌入链路收尾（延续 08-29）

### 完成的修复
1. **ffmpeg 抽帧方案切换**：`fps` 滤镜（需解码全片，且超低 fps 触发 muxer bug）→ `-ss` input seek 均匀抽帧（时间点 t_i=(i+0.5)*dur/n，单进程多输出）。实测 106s/1080p 抽 8 帧 0.43s（fps 滤镜 3.2s）。同时抽帧时 scale 最长边 560（只缩不放大）。
2. **视频嵌入 2 分钟瓶颈定位**：不是分辨率问题（scale 后依旧），是 transformers 5.16 的 Qwen3VL 视频处理**默认不启用 cap_pixels_per_frame**，短片段耗尽整段视频像素预算（4 帧 560×316 → 6060 tokens，前向 74.5s）。`embedder.processor.cap_pixels_per_frame = True` 后前向 32.6s（8 帧 34.2s，与帧数基本无关）。注意：input_ids 长度不变（6060 是固定预算），耗时减半来自实际计算量变化。
3. **独立脚本 0xC0000002 崩溃 = GPU 争用**（服务在跑时另开实例），非代码缺陷。独占 GPU 时独立脚本正常。
4. **manage.py 三个缺陷修复**：
   - stop/start 只认 pid 文件 → 增加 `_port_pids()`（netstat 按端口找真身）
   - netstat 中文 Windows 输出 GBK，text=True 默认 utf-8 解码崩 → `encoding="utf-8", errors="replace"`
   - Windows venv python.exe 是 launcher，Popen 拿到 launcher pid → health up 后按端口校准 pid 文件
5. **CUDA OOM 波动**：模型 4.3GB + 系统 GPU 进程（QQ/Edge/壁纸等）~1GB = 5.3GB，8GB 卡尚有余量；但系统进程波动时偶发 OOM，重试即可。

### 最终性能（RTX 5060 / 8GB / torch 2.11.0+cu128）
- 冷启动（模型加载）：~40s
- /embed（文本）：热态 ~1s
- /embed-image：~1.1s（1080p 单帧）
- /embed-video 8 帧：热态 83.6s（含显存紧张因素）
- /embed-segments 混合（视频4帧+图+文本）：热态 56.6s，**items=3 → vectors=3 等长** ✓

### 验收结论
视频时序理解链路全通：ffmpeg 时序抽帧 → Qwen3-VL 多模态嵌入 → 每片段独立 2048 维向量（norm≈1）。适合离线批量入库（单视频片段 ~1 分钟级，多片段可 batch）。
